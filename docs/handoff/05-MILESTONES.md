# 05. 개발 단계와 완료 기준

## 개발 방식
- 기본 기능을 먼저 만들어 직접 써 보며 고친다. 구현 → 사용 → 문제 확인 → 수정을 반복한다.
- 데이터 구조, 고유 ID, 저장 안정성은 처음부터 제대로 만든다. [03-DATA-FORMAT.md](03-DATA-FORMAT.md)와 [02](02-CURRENT-IMPLEMENTATION.md) F절의 계약을 깨는 변경은 하지 않는다.
- 단계마다 `npm test`가 모두 통과해야 하고, 새 기능에는 그 기능의 계약을 확인하는 테스트를 추가한다.
- **코드나 기초 함수가 있다는 것과 기능이 완성됐다는 것은 다르다.** 아래 완료 기준을 사용자가 실제 화면에서 해 볼 수 있어야 완료다.

## 단계와 순서

앞 단계를 끝내고 다음 단계로 간다.

| 순서 | 단계 | 내용 | 현재 상태 |
|---|---|---|---|
| 1 | M1 | 기본 프로그램: 프로젝트·Workspace·에셋 라이브러리·저장·복구 | 부분 구현 |
| 2 | M2 | STEP 1 Reference + STEP 2 2D 설계 | 부분 구현 |
| 3 | M3 | 지형·도로 연결: 도로가 지형을 따라감, 평탄화·절토·성토, 교차로 | 미구현 |
| 4 | M4 | 연결 규칙: 옹벽·계단·경사로·다리 자동 생성, 경계·보행 경로 검사 | 미구현 |
| 5 | M5 | Blender·Unreal 5.8·Unity 6 출력 | 좌표 변환 함수만 있음 |
| 6 | M6 | 모듈 건물 | 미구현 (건물은 외곽선을 위로 올린 볼륨뿐) |
| 7 | M7 | Git + LFS 동기화 | 미구현 |

M5까지 끝나면 땅·길·계단·다리가 있는 마을을 Blender로 넘겨 볼 수 있다. 그동안 건물은 단순 볼륨으로 출력되고, M6에서 모듈 건물이 되면 출력도 함께 확장한다.

## M1 기본 프로그램

### 남은 것
| 항목 | 현재 |
|---|---|
| 프로젝트 전용 에셋을 공용으로 등록 | 없음 |
| 에셋 분류(스타일·태그·부품·텍스처 용도) | 공용 에셋만 가능, 프로젝트 전용 에셋은 불가 |
| 에셋 정보 화면 | 정점·크기·UV 채널 일부만. UV 겹침·LOD·충돌·텍셀 밀도 없음. TGA/EXR 미리보기 없음 |
| 홈 화면 모델 썸네일 | 완성 여부 확인 필요 |
| 사용 중인 에셋 숨김·보관 | 확인 필요 |
| 실행 경로 정리 | `server.js`·`npm run dev:web`·`test:ui`가 옛 저장 방식을 사용. `release-0.4.2`에 빌드 폴더 여러 개가 섞여 있음 |
| 설치 파일 | 설치·업데이트·제거 전체 과정 미검증 |

### 완료 기준
- [ ] `npm test`가 모두 통과한다. 외부 도구(PhotoCraft·Blender 테스트 파일)가 필요한 테스트는 준비 방법이 02에 적혀 있다.
- [ ] 실행 방법이 하나로 정리돼 있다. 개발 실행·테스트가 모두 현재 저장 방식(FoundationStore)을 쓴다.
- [ ] 설치 파일로 설치 → 실행 → 프로젝트 생성·저장 → 업데이트 설치 → 같은 프로젝트 열기 → 제거까지 문제없다.
- [ ] 홈에서 프로젝트 만들기 / 열기 / 에셋 라이브러리 / 설정이 모두 동작한다.
- [ ] 모델(FBX/GLB)과 텍스처를 공용·프로젝트 전용으로 등록하고, 프로젝트 전용 에셋을 공용으로 올릴 수 있다. 올려도 원래 프로젝트의 참조는 그대로다.
- [ ] 같은 파일을 다시 등록하면 중복이 생기지 않는다.
- [ ] 에셋을 "파일 업데이트"로 갱신하면 Asset ID는 그대로고, 라이브러리에 항목이 하나만 보인다. 다른 프로젝트는 고정된 파일을 계속 쓴다.
- [ ] 에셋 상세에 3D 미리보기, 텍스처, 정점·삼각형·UV 채널, 사용 중인 프로젝트가 보인다. 측정하지 않은 값은 표시하지 않는다.
- [ ] 사용 중인 에셋은 지울 수 없고 숨기기·보관만 된다.
- [ ] 저장 도중 프로그램을 강제로 끄고 다시 열어도 마지막 정상 상태 또는 복구 후보가 나온다.

## M2 STEP 1·2

### 남은 것 — STEP 1
| 항목 | 현재 |
|---|---|
| **지도 화면의 목적과 사용 순서** | 화면만 보고는 무엇을 하는 곳인지, 다음에 무엇을 해야 하는지 알 수 없다. 의도한 흐름(범위 지정 → 캡처 → 이미지 편집 → STEP 2 트레이싱)이 화면에 드러나지 않는다 |
| **지도 작업 범위 지정** | 의도: 지도 위에서 사각형으로 범위를 지정하고 면적·둘레·축척을 보며 캡처. 현재: 화면에 보이는 영역 전체를 등록하며, 등록 버튼("지도에서 자료 만들기")이 왼쪽 아래에 떨어져 있어 찾기 어렵다 |
| **지도 그리기 도구 동작 안 함** | "선 그리기"를 눌러도 선이 그려지지 않고 지도만 움직인다. 도구 줄(선 그리기·폴리곤 그리기·선택·정점 편집)이 반응하지 않는다. 원인 미확인 |
| **지도 위 그림의 쓰임** | 그린 선·폴리곤은 "벡터 자료"로 따로 저장될 뿐 어디에도 쓰이지 않는다. 무엇을 위해 그리는지 알 수 없다 |
| 지도 위 축척·좌표 표시 | 없음 |
| 손그림·지도 캡처 → 편집 → 축척 확정 → 트레이싱 → STEP 2 저장·재열기 전체 흐름 | 기능은 따로 있으나 처음부터 끝까지 이어서 검증되지 않음 |
| 이미지 분석 후보 → 설계 객체 | 선 후보는 Road, 영역 후보는 Building/Water/Zone으로만. 도로 중심선·폭, 지형 구역 변환 없음 |
| 지도 위에 그린 선·폴리곤 → 설계 객체 | 저장·측정만 되고 Road/Building으로 바뀌지 않음 |
| 같은 이미지의 여러 분석 기록 중 하나 다시 열기 | 수정됨, 실제 실행 확인 필요 |

### 남은 것 — STEP 2
| 항목 | 현재 |
|---|---|
| **그리는 중 Ctrl+Z** | 선을 그리는 도중 Ctrl+Z를 누르면 마지막 점만 지워지는 게 아니라, 그리던 선과 함께 **이전에 완성한 객체(예: 구역)까지 사라진다**. 원인: 전역 단축키(`src/shell/foundation.js`)가 그리기 상태를 확인하지 않고 프로젝트 실행 취소를 실행함. 무엇이 취소됐는지 알림도 없다 |
| **곡선 그리기** | 모든 선·외곽선이 점과 점을 직선으로만 잇는다. 곡선(곡선 핸들로 휘게 하기)을 만들 수 없다. 저장 형식도 점 목록뿐이라 곡선 정보를 담지 못한다 |
| 0.5m 모듈 스냅과 보정값 미리보기 | 화면 좌표 1m 반올림만 있음 |
| 작업 모드(모듈 설계 / 실측 재현 / 자유 편집) | 없음 |
| 도로 그래프(연결 노드, 교차로) | 도로는 각각 독립된 선. 서로 연결되지 않음 |
| 객체 속성 | 도로 유형·최대 경사·지형 상호작용, 건물 스타일·블록아웃 수준, 구역 용도·밀도·배치 제한 없음 |
| 건물 외곽 프리셋(L자·ㄷ자), 출입구 방향 | 없음 |
| 겹침 경고 처리 | 경고만 하고 "이 겹침은 허용" 같은 선택을 저장하지 못함 |

### 완료 기준
- [ ] 손그림 이미지 하나로 시작해 편집 → 두 점 축척 확정 → 도로·건물 트레이싱 → 저장 → 다시 열기까지 한 번에 된다.
- [ ] 처음 쓰는 사람이 설명 없이도 지도 화면에서 무엇을 하고 다음에 어디로 가는지 알 수 있다.
- [ ] 지도 위에서 사각형으로 작업 범위를 지정하면 면적·둘레·축척이 보이고, 그 범위를 캡처해 Image Workspace로 보낼 수 있다.
- [ ] 지도 영역을 캡처해 같은 흐름을 할 수 있고, 다시 열면 지도와 정확히 겹친다.
- [ ] "선 그리기"·"폴리곤 그리기"를 누르고 지도를 클릭하면 점이 찍히고 선·면이 그려진다. 그리는 동안 지도가 움직이지 않는다.
- [ ] 지도 위에 그린 선·폴리곤이 무엇에 쓰이는지 화면에 나오고, 실제로 그 용도(설계 객체로 변환 등)로 이어진다.
- [ ] 원본 이미지는 어떤 편집 후에도 바뀌지 않는다.
- [ ] 축척이 확정되지 않은 이미지에 연결된 도형은 3D로 생성되지 않고, 이유가 화면에 보인다.
- [ ] 이미지 분석 후보를 확인·수정·승인하면 도로는 중심선과 폭을 가진 Road, 영역은 지정한 종류의 객체가 된다. 승인하지 않은 후보는 객체가 되지 않는다.
- [ ] 지도 위에 그린 선·폴리곤을 Road·Building 등 설계 객체로 바꿀 수 있다.
- [ ] 선·외곽선을 그리는 도중 Ctrl+Z를 누르면 마지막으로 찍은 점 하나만 지워진다. 이미 완성된 객체는 그대로다. 그리기가 끝난 뒤의 Ctrl+Z는 마지막 작업 하나만 취소하고, 무엇이 취소됐는지 화면에 잠깐 보인다.
- [ ] 도로·지형 경계·수역·구역을 그릴 때 점마다 직선 꺾임 또는 곡선을 고를 수 있고, 곡선은 핸들로 휘는 정도를 조절할 수 있다. 그린 뒤에도 점을 직선↔곡선으로 바꿀 수 있다.
- [ ] 곡선은 저장 후 다시 열어도 같은 모양이고, 3D로 생성할 때 같은 모양을 따라간다.
- [ ] 0.5m 모듈 스냅을 켜면 건물 외곽 치수가 스냅 간격에 맞춰지고, 적용 전 보정값이 미리 보이며, 원본 치수는 따로 남는다.
- [ ] 도로 끝을 다른 도로에 붙이면 연결 노드가 생기고, 한쪽을 움직여도 연결이 유지된다.
- [ ] 01 명세 6.1의 객체 속성을 속성 패널에서 입력·저장할 수 있다.
- [ ] 2D에서 그린 도형의 치수가 3D 결과와 일치한다(오차 1mm 이하).
- [ ] 저장 후 다시 열어도 모든 객체의 ID·속성·레이어가 그대로다.
- [ ] 도로 폭을 바꿔도 주변 건물 데이터(ID·위치·속성)가 바뀌지 않는다.

## M3 지형·도로 연결
- [ ] 도로마다 Follow(지형 따라감) / Conform(평탄화·절토·성토) / Bridge, 건물마다 Follow / 바닥 평탄화 / 기초를 고를 수 있다.
- [ ] 도로를 그리면 지형 높이를 따라 3D로 생성되고, 최대 경사를 넘는 구간은 경고가 나온다.
- [ ] 광장(구역)을 평탄화하면 그 영역의 지형만 평평해지고, 원본 지형은 따로 남는다.
- [ ] 건물을 지우면 그 건물이 만든 지형 평탄화도 사라진다.
- [ ] T자·십자 교차로가 틈 없이 생성된다.
- [ ] 지형을 바꾸면 영향받는 도로·건물만 다시 계산되고, 잠근 객체는 움직이지 않고 경고만 나온다.
- [ ] 충돌이 생기면 해결 방법 목록이 나오고, 사용자가 고르기 전에는 아무것도 옮겨지지 않는다.

## M4 연결 규칙
- [ ] 높이가 다른 두 지형이 만나는 경계에 옹벽이 자동으로 생긴다.
- [ ] 도로가 높이 차가 있는 경계를 넘으면 계단 또는 경사로가 자동으로 생긴다. 어느 쪽으로 할지 고를 수 있다.
- [ ] 도로가 수로를 건너면 다리가 자동으로 생긴다.
- [ ] 자동으로 생길 구조물은 적용 전에 미리보기로 보이고, 승인해야 만들어진다.
- [ ] 도면(도로 위치·폭, 구역 높이)을 바꾸면 관련된 옹벽·계단·다리만 다시 만들어진다. 사용자가 직접 고친 구조물은 유지된다.
- [ ] 계단 맨 위와 땅 사이, 다리와 도로 사이 같은 경계의 틈과 높이 불일치를 검사하고 위치를 3D에 표시한다.
- [ ] 사람이 지나갈 길(도로·계단·다리를 이은 경로)의 경사·턱·끊김을 검사한다.

## M5 출력
- [ ] 장면을 Blender용 FBX/GLB로 내보내면 1BU=1m, Z-Up, 원점·피벗·이름·계층이 01 명세 8.3과 같다. 지형·도로·옹벽·계단·다리·건물(볼륨)이 모두 포함된다.
- [ ] 같은 장면을 다시 내보내도 오브젝트 이름과 ID가 바뀌지 않는다.
- [ ] Unreal 5.8과 Unity 6에서 가져온 배치가 Studio와 위치·회전·크기가 일치한다.
- [ ] 엔진에 가져올 때 기본 PBR 머티리얼이 만들어지고 BaseColor·Normal·ORM이 올바른 색공간으로 연결된다.
- [ ] 모델 하나의 여러 Material Slot에 서로 다른 텍스처(트림 + 고유 텍스처)를 연결할 수 있다.
- [ ] 같은 트림 텍스처를 쓰는 모델을 여러 개 가져와도 엔진 프로젝트에 텍스처가 하나만 있다.
- [ ] 다시 가져올 때 엔진에서 수정한 머티리얼이 덮어써지지 않는다.

## M6 모듈 건물
- [ ] 모듈(벽·코너·문·창·지붕)을 FBX/GLB로 등록하고 치수·피벗·Socket·길이 변형 허용 여부를 지정할 수 있다.
- [ ] 직사각·L자·ㄷ자 외곽선에서 벽·바닥·기본 지붕(박공·외쪽·평지붕)이 모듈로 조립된다.
- [ ] 남는 길이는 01 명세 7.3 순서로 처리되고, 문·창·코너·장식 모듈은 늘어나지 않는다.
- [ ] 자동으로 못 만든 구간은 3D에 표시되고 이유가 나오며, 나머지는 정상 생성된다.
- [ ] Recipe를 바꿔도 기존 건물은 그대로이고, 선택한 건물에만 적용된다. 적용 전 미리보기가 있다.
- [ ] 사용자가 직접 바꾼 부품(Override)은 재생성 후에도 남는다.
- [ ] 같은 입력·같은 Recipe·같은 시드로 다시 생성하면 결과가 동일하다.
- [ ] Rule Inspector에서 선택한 모듈이 왜 선택됐는지(스타일·크기·Socket·자동/고정) 확인할 수 있다.
- [ ] 블록아웃 수준 A와 B를 건물마다 바꿀 수 있고, 바꿔도 건물 ID가 유지된다.
- [ ] 조립된 건물이 지형 위 배치 방식(M3)을 따르고, M5 출력에 부품 단위 계층으로 포함된다.
- [ ] (06 11번 결정에 따라) Blender 애드온으로 모듈을 등록·갱신·검사할 수 있고, 애드온 없이 FBX/GLB 파일로도 같은 작업이 된다.

## M7 동기화
- [ ] 원격 저장소를 연결하지 않아도 로컬에서 모든 기능을 쓸 수 있다.
- [ ] PC A에서 저장한 프로젝트를 PC B에서 열면 같은 상태가 된다(에셋 파일 포함).
- [ ] 두 PC에서 같은 프로젝트를 동시에 수정하면 충돌이 표시되고 양쪽 작업이 모두 보존된다.
- [ ] 오프라인에서 저장한 작업은 "로컬 저장됨"으로 표시되고, 연결되면 올라간다.
- [ ] 동기화가 실패하면 실패로 표시된다. 성공처럼 보이지 않는다.
- [ ] 사용자가 Git 명령이나 용어를 몰라도 위 과정을 모두 할 수 있다.
- [ ] 공용 라이브러리와 프로젝트가 서로 다른 저장소로 동기화된다.
