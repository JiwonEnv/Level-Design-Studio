# Level Design Studio 결정사항

`Chat_Screenshot/` 대화에서 최종 결정된 사항만 정리했다.

---

## 1. 프로그램 성격

- 건축물만이 아니라 맵 전체(지형·도로·건물·수로·환경)를 설계한다.
- 레퍼런스에서 출발한다. 실제 지도, 화면 캡처, 손그림 평면도를 가져와 프로그램 안에서 평면도를 만든다.
- 결과물은 Blender 모델링용 구조화 블록아웃이다. 크기·피벗·오브젝트 분리·이름까지 정리하고, 실제 모델링은 Blender에서 한다.
- AI가 제안하고 사용자가 승인하는 혼합형으로 운영한다.
- STEP 1 Reference / STEP 2 2D 설계 / STEP 3 생성 / STEP 4 3D 편집·출력 구조를 유지한다. 순서는 강제하지 않는다.
- 하나의 데스크톱 프로그램으로 만든다.

## 2. 데이터와 좌표

- 2D·3D가 함께 쓰는 공통 Scene Model이 원본이다. 3D 메시는 다시 만들 수 있는 결과물이다.
- 블록아웃 상세도는 A(기본 형태)로 시작해 B(벽·층·지붕·문·창 분리)를 기본으로 하고, C(세부 부품)까지 확장한다. 수준은 건물마다 지정하고, C는 부품별로 고른다.
- 단위는 m, 오른손 좌표계, Z-Up이다. 원점은 자동으로 정한 뒤 사용자가 바꿀 수 있고, 원점을 바꿔도 실제 배치는 유지된다.

## 3. STEP 1 Reference

- Image Workspace와 Map Workspace를 한 프로그램 안에 둔다.
- 지도 영역을 캡처해 Image Workspace로 가져와 수정한다. 이때 좌표·축척·회전 값을 함께 보존한다.
- 손그림이나 외부 캡처만으로 Image Workspace를 단독으로 쓸 수 있다.
- 치수 보정은 0.5m 스냅 보정값을 미리 보고 적용한다. 원본 치수는 보존한다.

## 4. 지형

- 지형 경계 처리는 Cliff(절벽), Blend(자연 연결), Platform(플랫폼) 세 가지를 모두 지원한다.
- 지형 위 배치는 객체마다 고른다.
  - Follow: 지형을 따라감
  - Conform: 평탄화·절토·성토
  - Foundation/Bridge: 기초·옹벽·교량
- 자연 지형, 평탄화 구역, 절벽, 교량, 계단식 지형, 동굴·터널까지 모두 작업할 수 있는 구조로 설계한다.

## 5. 생성과 재생성

- 재생성은 자동·수동 혼합이다. 바뀐 부분만 다시 만들고, 사용자가 수정한 부분은 보호한다(잠금·Override).
- 충돌은 감지만 하고, 해결 방법은 사용자가 고른다. 잠근 객체는 자동으로 옮기지 않는다.
- 구조물은 공통 모듈과 구조물별 생성기로 만든다. 건물은 외곽선, 도로·성벽·수로는 경로, 성·시장·고가는 복합 생성기를 쓴다.
- 구조물 사이 연결은 자동으로 분석해 미리보기를 보여주고, 승인하면 적용한다.
- 복잡한 건물은 가능한 부분만 자동으로 만들고, 문제 구간은 표시해서 사용자가 보완한다.

## 6. 건물

- 생성 방식은 완성 건물 배치, 모듈 자동 조립, 스타일 변형을 섞어 쓴다.
- 3D 편집은 이동·회전·크기, 벽·지붕 개별 선택, 건물 모서리 제어점 이동까지 한다. 자유 메시 편집과 UV는 Blender에서 한다.
- 구조는 Module Library → Building Recipe → Variant → Instance이다. 필수 구조 모듈은 삭제할 수 없고, 기존 건물을 자동으로 바꾸지 않는다.
- 모듈을 수정하면 기존 건물에 반영할지 선택한다. 반영하지 않으면 기존 상태를 유지한다.
- 0.5m 그리드와 모듈 규격에 맞춰 스냅해, 애매한 치수가 처음부터 생기지 않게 한다.
- 스타일별 에셋 분류와, 지금 적용된 모듈 규칙을 확인하는 화면(Rule Inspector)을 둔다.

## 7. 에셋

- 공용 라이브러리는 모델(FBX)과 텍스처만 공유한다. 프로젝트는 목록으로 참조만 하고 파일을 복제하지 않는다.
- 에셋을 수정할 때마다 v1, v2를 새로 만들지 않는다. Asset ID는 그대로 두고 파일만 갱신하며, 이력은 Git이 관리한다. 프로젝트마다 쓰는 상태를 고정하고, 업데이트는 골라서 적용한다.
- 사용 중인 에셋은 삭제하지 않고 숨기거나 보관한다.
- 에셋 정보 화면에 정점·삼각형·UV·LOD 같은 정보, 텍스처, 사용 중인 프로젝트를 표시한다.

## 8. Blender 연동

- FBX/GLB 직접 가져오기를 먼저 만들고, Blender 애드온은 그다음에 만든다.
- 등록 단위는 모듈·그룹·완성형 중에서 고른다.
- 메시·UV는 Blender가, Socket·Recipe·배치는 Studio가 관리한다. 양쪽에서 모두 바뀌면 충돌로 표시한다.
- 업데이트는 개별로도, 여러 개를 골라 한꺼번에도 할 수 있다.
- 에셋은 고유 ID로 추적하고, 불확실한 변경만 사용자에게 확인한다.
- 에셋 하나에 원본 .blend 여러 개를 연결할 수 있다.
- 라이브러리 모델은 FBX로 다운로드한다(GLB 추가 지원).

## 9. 머티리얼·텍스처

- 머티리얼과 파라미터는 공유하지 않고 프로젝트마다 만든다.
- Studio는 FBX를 엔진에 넣을 때 기본 PBR 머티리얼을 만들고 텍스처를 연결한다. 트림 같은 공용 텍스처가 중복으로 들어가지 않게 한다.
- 셰이더 생성·연결은 각 엔진 프로젝트를 작업하는 AI가 맡는다.
- 텍스처는 Trim Sheet / Tileable / Special 세 가지로 나누고 폴더도 분리한다. Special은 이미지 파일만 등록한다.
- 한 모델 안에서 부위마다 다른 텍스처를 쓰는 경우와, 같은 표면에 텍스처를 겹치는 경우를 모두 고려한다.
- 다시 가져올 때 기존 엔진 머티리얼을 덮어쓰지 않는다.

## 10. 저장과 동기화

- 프로그램은 PC마다 설치하고, 데이터는 Workspace 폴더로 분리한다.
- PC 간 자동 동기화는 필수다. Git + Git LFS를 쓰고, Studio가 자동으로 처리해서 사용자는 Git을 몰라도 된다.
- 공용 라이브러리는 별도 저장소로, 프로젝트는 프로젝트마다 저장소를 둔다. 충돌이 나도 자동으로 덮어쓰지 않는다.
- 로컬 저장을 먼저 한다. 프로그램이 업데이트돼도 이전 프로젝트를 열 수 있어야 한다.

## 11. 사용성

- 프로그램은 쉬워야 한다. 내부 관리는 숨기고, 일상 작업은 한두 번 조작으로 끝낸다.

## 12. 개발 방식

- 기본 MVP를 먼저 만들고, 직접 써 보며 고친다. 데이터 구조와 ID는 첫 버전부터 제대로 만든다.
