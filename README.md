# Level Design Studio — Windows 레벨 편집 MVP 0.3

독립 프로그램 창에서 프로젝트·에셋·3D 배치를 편집하고 로컬 파일에 저장하는 첫 데스크톱 버전입니다. 프로그램 실행에 브라우저·Node.js 설치·개발 서버·인터넷 연결이 필요하지 않습니다. STEP 1~4 전체 설계를 유지하며 아직 미구현인 기능은 아래에 구분합니다.

## 실행과 설치

- 설치: `release-0.3/Level-Design-Studio-Setup-0.3.0.exe`를 실행합니다. 설치 위치 선택과 바탕화면/시작 메뉴 바로가기를 지원합니다.
- 설치 전 실행: `release-0.3/win-unpacked/Level Design Studio.exe`를 실행합니다. 이 파일만 복사하지 말고 `win-unpacked` 폴더 전체를 함께 옮겨야 합니다.
- 이 프로젝트 폴더에서는 `Start-Studio.cmd`를 더블클릭해도 독립 프로그램을 엽니다.
- 기본 저장 폴더는 Windows 문서 폴더 안의 `Level Design Studio/Workspace`입니다. 화면 하단에서 실제 저장 위치를 확인하고 탐색기로 열 수 있습니다.
- 이전 웹 MVP 데이터를 이어 쓰려면 하단 **작업 폴더 열기**에서 기존 `studio-workspace` 폴더를 선택하세요. 파일을 임의 이동·변환하지 않으며 Asset ID와 저장 형식을 유지합니다.
- 마지막 작업 폴더와 프로젝트를 기억합니다. 저장 중 종료를 요청하면 저장이 끝날 때까지 기다립니다. 저장 실패 시 계속 편집하거나 명시적으로 저장하지 않고 종료할 수 있습니다.

설치 파일은 서명되지 않은 개발용 빌드입니다. Windows 배포 서명과 실제 설치/제거 과정의 검증은 후속입니다. 현재는 패키징된 실행 파일의 실행·저장·재시작을 검증했습니다.

## 개발·빌드

개발 환경은 Node.js 22.12 이상 또는 24 LTS와 npm이 필요합니다. Electron 45.3.1을 이번 MVP 셸로 사용합니다. 기존 Tauri 제안은 확정 이력으로 바꾸지 않고 대안으로 유지합니다.

`npm ci` 후 `npm run desktop`으로 개발용 독립 프로그램을 실행합니다. `npm run package:win`으로 Windows x64 설치 파일을 만듭니다. 제작 도구를 처음 내려받는 과정에는 인터넷이 필요합니다.

`npm test`: 저장 및 데스크톱 프로토콜 검사. `npm run test:desktop`: 실제 Electron 창에서 오프라인 생성·모델 표시·저장·재실행·작업 폴더 전환·저장 충돌·종료 보호 검사. 패키징된 실행 파일은 `node scripts/test-desktop.mjs "release-0.3/win-unpacked/Level Design Studio.exe"`로 검사합니다.

브라우저용 기존 검증 경로는 `npm run dev:web`, `npm run test:ui`, `Start-Web-Preview.cmd`로 남겼습니다. 데스크톱 제품은 HTTP 서버를 사용하지 않고 `studio://app/` 내부 프로토콜로 묶인 화면과 로컬 저장소를 연결합니다. UI에는 Node.js·파일시스템 API를 직접 노출하지 않습니다.

## 모델 라이브러리 사용

1. **새 프로젝트**에 이름을 입력합니다.
2. 왼쪽에서 **공용 / 프로젝트**를 선택하고 **등록** 또는 파일 드롭으로 에셋을 가져옵니다.
3. 모델의 **배치**를 누릅니다. 오른쪽 숫자 또는 3D 조작 도구로 위치·회전·배율을 바꿉니다.
4. **로컬에 저장됨**을 확인합니다. 다시 실행한 뒤 상단에서 프로젝트를 선택하면 복원합니다.
5. 모델 수정본은 해당 에셋 상세의 **파일 갱신**을 사용합니다. 라이브러리에는 같은 항목 하나가 유지됩니다. 기존 프로젝트는 이전 파일을 계속 사용하고, 상세에서 **이 프로젝트에 갱신 적용**을 선택할 수 있습니다.

FBX는 센티미터, GLB는 미터를 기본 입력 단위로 제시합니다. 실제 파일 단위가 다르면 배치 선택 후 오른쪽 **입력 단위**를 변경하세요. 내부 장면은 미터·Z-Up·오른손 좌표계입니다. GLB의 Y-Up을 표시용으로 변환하며 원본 파일은 변경하지 않습니다. FBX 축 방향의 자동 판별·변환은 아직 없습니다.

## 현재 구현

| 영역 | 사용 가능한 범위 |
|---|---|
| 공통 | 독립 Windows 프로그램·프로젝트·파일 저장·마지막 작업 복원·Undo/Redo·저장 충돌/종료 보호 |
| Scene | Terrain/Road/Building/Water/Zone/Prop, 안정적 ID·레이어·참조·기본 의존 관계 |
| STEP 1/2 | 실제 이미지 위 선·자유 폴리곤·사각형·점 입력, 두 점 축척·정점/객체 드래그·숫자 편집·스냅·레이어 |
| STEP 3 | 전체/선택 미리보기·적용·취소. 기본 표면·도로 리본·건물 볼륨·수면·구역·프랍 생성 |
| STEP 4 | FBX/GLB·생성 결과 표시, 카메라·Gizmo, 직접 변형·잠금·복제, 생성 객체 변형 보호 |
| 에셋 | 동일 Asset ID 갱신·해시 중복 방지·공용/전용·프로젝트 파일 고정·기본 텍스처 참조 |

연결한 외부 텍스처는 현재 **참조·파일 관리만** 지원하며 3D 머티리얼에 자동 적용되지 않습니다. 모델에 내장된 기본 재질은 로더가 표시합니다. 외부 파일 경로와 네트워크 텍스처는 차단합니다. FBX의 모든 재질·애니메이션 호환성을 보장하지 않습니다. Draco/KTX2 압축 GLB 디코더는 미구현입니다. 파일당 48MB 제한입니다.

## 데이터 위치와 보존

이전 웹 MVP는 기본 `studio-workspace/`에 `library.json`, `projects/<UUID>.json`, `blobs/<SHA-256>`을 저장합니다. `STUDIO_WORKSPACE` 환경변수로 실행 전에 다른 데이터 폴더를 지정할 수 있습니다. 프로젝트와 공용 에셋 참조는 ID·해시를 사용하므로 Workspace 전체를 옮겨도 절대 경로에 의존하지 않습니다.

브라우저 임시 저장소가 아니라 디스크 파일에 저장합니다. 최신 포인터를 갱신해도 이전 프로젝트가 사용하는 파일은 유지합니다. 동일 바이트는 한 번만 보관합니다. 같은 에셋을 갱신해도 `v1/v2` 항목이나 이름 복제를 만들지 않습니다. **새 내용의 바이트는 이전 프로젝트 보호를 위해 남기므로 저장 공간은 증가할 수 있습니다.** 자동 이력 정리·삭제는 구현하지 않았습니다. 이를 무제한 보관·동기화가 완성됐다는 의미로 해석하지 않습니다.

파일 저장은 한 작업 폴더당 단일 프로그램에서 사용합니다. 데스크톱은 중복 실행을 기존 창으로 연결합니다. 웹 미리보기와 데스크톱이 같은 폴더를 동시에 편집하는 방식은 지원하지 않습니다. 별도 저장소 분리와 객체별 JSON 분할은 다음 단계이며, 현재는 하나의 라이브러리 목록과 프로젝트별 JSON입니다. `.bak` 복원은 수동입니다. 저장 실패 시 화면 편집을 유지하고 추가 저장을 멈춥니다. **장면 기록 다운로드**로 현재 JSON을 보존하고 문제 해결 후 다시 실행하세요. 이 다운로드에는 실제 모델·이미지 파일이 포함되지 않으며 재가져오기 UI는 아직 없습니다.

## 명확히 미구현

지도·캡처·지도 재중첩, PhotoCraft/OpenCV/SAM 통합, 이미지 원근/레이어 편집, 지형 브러시·등고선·절벽, 도로 교차로 접합·지형 추종·수로·교량, 모듈 조립·Socket·스타일·Variant, 의존성 기반 부분 재생성, Blender 애드온·출력, Unreal/Unity 출력·Importer, Git/LFS 실제 동기화, 클라우드·다른 PC 왕복 검증, 원본 .blend/.spp/.sbs 등록, 텍스처 세트 ZIP, 고급 품질 검사와 데이터 마이그레이션은 미구현입니다.

JSON 다운로드는 **Studio 장면 기록**이며 Unreal/Unity 내보내기가 아닙니다. GLB를 FBX로 변환하지 않습니다. 등록한 FBX 원본만 FBX로 내려받을 수 있습니다. 미래 버전이나 엔진 호환성을 검증했다고 주장하지 않습니다.

## 검증

```powershell
npm test
npm run test:ui
npm run build
```

브라우저 검증 최초 실행에는 `npx playwright install chromium`이 필요합니다. API 테스트는 임시 데이터 폴더, 화면 테스트는 `.test-workspace/`를 사용하며 사용자의 기본 Workspace를 건드리지 않습니다. 간단한 자체 생성 GLB/ASCII FBX 삼각형으로 가져오기 경로를 검사하므로 복잡한 실제 제작 파일 전체의 호환성 테스트를 대체하지 않습니다.
