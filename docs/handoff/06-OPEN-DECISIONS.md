# 06. 결정이 필요한 것

개발을 이어가기 전에 정해야 하는 항목이다. 정해지면 해당 내용을 [01-PRODUCT-SPEC.md](01-PRODUCT-SPEC.md)로 옮기고 여기서 지운다.
**정해지지 않은 항목을 개발자가 임의로 정하지 않는다.** 막히면 질문한다.

| # | 항목 | 선택지 | 권장 |
|---|---|---|---|
| 1 | Git LFS 용량·이력 보존 | 전체 이력 보존 / 일정 기간·개수만 보존 / 사용자가 수동 정리 | 결정 필요. 저장 공간 정리(GC) 기능과 함께 정한다 |
| 2 | 이미지 → 2D 자동 변환 범위 | 수동 트레이싱 + OpenCV 후보만 / SAM 2 클릭 선택 추가 / 지도 의미 분할까지 | 수동 + OpenCV 후보로 유지하고 SAM 2는 M7 이후 |
| 3 | 모듈 기본 규격 | 스타일별 프리셋 값(예: 폭 2m, 층고 3m, 벽 0.2m) / 사용자가 모듈 등록 시 정의 | 첫 테스트 키트 하나의 실제 값으로 시작. 고정 표준으로 만들지 않음 |
| 4 | 엔진에서 고친 머티리얼·충돌 설정을 재출력 때 보존하는 방법 | 엔진 쪽 소유로 두고 Studio는 건드리지 않음 / 변경 감지 후 확인 | 결정 필요. M5 시작 전에 정한다 |
| 5 | 같은 표면에 겹치는 텍스처(이끼 등)의 영역 표시 방법 | 마스크 텍스처 / Vertex Color / 별도 UV 채널 | Blender → Unreal 실제 테스트 후 결정 |
| 6 | 에셋 파일 크기 한도 | 현재 48MB 유지 / 상향 | 결정 필요 |
| 7 | ORM vs Unity HDRP Mask Map 채널 차이 | 출력 시 변환 / 엔진 쪽 처리 | M5에서 Unity 출력 시 결정 |
| 8 | 건물 외곽선의 곡선 허용 | 허용(곡선 벽은 짧은 직선 모듈로 나눠 조립) / 건물은 직선만 | 결정 필요. 모듈 조립 규칙과 함께 정한다 |
| 9 | 2D 설계 편집기 | 지금 직접 만든 편집기를 보강(곡선·실행 취소) / Terra Draw 기반으로 교체해 지도 화면과 통일 | 결정 필요. M2에서 정한다 |
| 10 | Python 도구 사용 방식 | Python을 별도 프로세스로 연결 / JavaScript 대체 라이브러리 사용 | 결정 필요. M3 시작 전에 정한다 |
| 11 | Blender 애드온 만드는 시점과 범위 | M6 모듈 건물과 함께(모듈 등록·갱신·검사) / M5 출력과 함께(장면 불러오기 포함) / M7 이후 | M6과 함께. 모듈을 Blender에서 만들어 등록·갱신하는 일이 가장 잦음. 장면 불러오기는 파일로 충분하면 넣지 않음 |

## 정해진 범위 밖 (지금 만들지 않음)
복잡한 비정형 건축, 실시간 다중 사용자 편집, Blender와 실시간 양방향 편집, 정점 단위 변경 분석, 고급 머티리얼·셰이더 편집, 자체 클라우드 서버, AI 자연어 수정.
