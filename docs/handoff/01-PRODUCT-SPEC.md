# 01. 제품 명세 — 무엇을, 왜 만드는가

이 문서는 결정된 사항만 담는다. 아직 정하지 않은 것은 [06-OPEN-DECISIONS.md](06-OPEN-DECISIONS.md)에 있다.
"후속"은 정해진 기능이지만 첫 단계에서 만들지 않는 것이다.

---

## 1. 목적

Level Design Studio는 **게임 레벨의 맵 전체를 설계해서 Blender 모델링과 게임 엔진 작업에 바로 쓸 수 있는 구조화된 블록아웃을 만드는 데스크톱 프로그램**이다.

- 지형·도로·건물·수로·구조물·환경을 한 곳에서 설계한다.
- 레퍼런스(실제 지도, 화면 캡처, 손그림 평면도)에서 출발해 프로그램 안에서 평면도를 만든다.
- 평면도에서 규칙으로 3D 블록아웃을 만든다. 블록아웃은 정확한 크기, 피벗, 오브젝트 분리, 이름, 계층까지 정리된 상태다.
- 실제 에셋 모델링(하이·로우폴리, UV, 텍스처)은 Blender/Substance에서 한다.
- 결과를 Unreal 5.8과 Unity 6으로 넘긴다.
- AI 기능은 제안만 하고 사용자가 승인해야 적용된다. AI가 메시를 직접 고치지 않는다.

### 해결하려는 일
1. **맵 전체를 한 곳에서 설계** — 지형·도로·광장·수로·건물·구조물을 한 도면에서 다룬다.
2. **레퍼런스에서 바로 시작** — 지도·캡처·손그림을 가져와 축척을 맞추고 그 위에 평면도를 그린다.
3. **반복 작업을 규칙으로 자동화** — 높이 차 → 옹벽, 길이 높이를 넘음 → 계단·경사로, 물을 건넘 → 다리. 도면을 고치면 관련 부분만 다시 만든다.
4. **Blender 모델링 준비를 끝내 둠** — 크기·피벗·이름·계층이 정리된 블록아웃을 넘겨 Blender에서는 모델링에만 집중한다.
5. **에셋을 여러 프로젝트에서 재사용** — 직접 만든 모델·텍스처를 여러 프로젝트가 함께 쓰고, 고쳐도 파일이 v1·v2로 늘어나지 않는다.
6. **엔진에 묶이지 않음** — Houdini나 특정 엔진 없이, 같은 레벨 데이터를 Unreal과 Unity 양쪽으로 넘긴다.
7. **어느 PC에서든 이어서 작업** — Git을 몰라도 자동으로 동기화된다.
8. **AI는 돕고 결정은 사용자** — AI가 제안하고 사용자가 승인한다. 직접 고친 부분은 다시 생성해도 지켜진다.

### 기존 도구와의 차이
위 흐름 전체(레퍼런스 → 평면 설계 → 연결 규칙 자동 생성 → Blender·엔진 출력 → 에셋 재사용·동기화)를 한 번에 하는 도구는 없다. 기존 도구는 한 부분만 하거나 특정 엔진에 묶여 있다.

| 도구 | 하는 일 | 차이 |
|---|---|---|
| CityGenerator, Unreal City Sample | 도시 자동 생성 | Unreal + Houdini 필요 |
| RoadForge | 도로 생성 | Unreal 전용 |
| Unreal PCG | 엔진 안 절차적 배치 | Unreal 전용 |
| Houdini | 범용 절차적 생성 | 상용·학습 부담. 연결 규칙은 직접 만들어야 함 |
| Esri CityEngine | GIS·규칙 기반 도시 생성 | 상용. 실제 도시 재현 중심 |
| BlenderGIS, OSM2World | 지도·지형 데이터를 3D로 | 레벨 설계 기능 없음 |
| BlenderLevelArchitect | Blender 안 블록아웃 | 레퍼런스·연결 규칙·엔진 출력 없음 |
| Mapforge | 지도 편집 | 2D 지도만 |
| Gaea, World Machine | 지형 생성 | 지형만 |

기존 도구는 그대로 쓰지 않고, 일부를 재사용하거나 방식을 참고해 다시 만든다 → [07-OPEN-SOURCE.md](07-OPEN-SOURCE.md).

### 만들지 않는 것
- Blender를 대체하는 정밀 모델링 기능 (자유 토폴로지, UV, 베이크, 스컬프팅)
- 셰이더·머티리얼 그래프 편집 (엔진 프로젝트에서 처리)
- 물 시뮬레이션, 구조 안전 계산

## 2. 설계 원칙 (모든 기능에 적용)

1. **공통 Scene Model이 원본이다.** 2D 편집과 3D 편집은 같은 데이터를 고친다. 3D 메시는 언제든 다시 만들 수 있는 결과물이다.
2. **모든 객체는 변하지 않는 고유 ID를 가진다.** 같은 입력·같은 규칙·같은 시드면 같은 결과가 나온다.
3. **사용자 수정은 보호한다.** 다시 생성할 때 바뀐 부분과 그 영향을 받는 부분만 다시 만들고, 사용자가 손댄 것(Override, 잠금)은 유지한다.
4. **위험한 변경은 미리보기 후 승인한다.** 자동으로 덮어쓰지 않는다. 원본 파일은 바꾸지 않는다.
5. **내부는 정교하게, 사용자는 단순하게.** 일상 작업은 한두 번 조작으로 끝나고, 문제가 없으면 묻지 않는다. Git·ID·버전 같은 내부 관리는 숨긴다. 단, 실패를 성공처럼 보여주지 않는다.
6. **특정 지형 전용이 아니라 여러 지형과 구조물을 조합하는 범용 도구다.**
7. **새 기능은 먼저 기존 구조(Scene Model, Dependency Graph, Override, 부분 재생성)로 해결되는지 확인한다.**

## 3. 화면 구조

```
홈: 프로젝트 만들기 / 프로젝트 열기 / 에셋 라이브러리 / 설정

STEP 1 Reference  →  STEP 2 2D 설계  →  STEP 3 생성  →  STEP 4 3D 편집·출력
         (순서를 강제하지 않는다. 언제든 오가며, 데이터는 자동으로 이어진다)

모든 STEP 공통: 에셋 라이브러리 · 속성 패널 · 저장 · 동기화 상태 · Undo/Redo
```

화면 참고: [04-SCREENS.md](04-SCREENS.md)

데스크톱 프로그램 기반은 **Electron**이다. 화면은 웹 기술(three.js, MapLibre 등)로 만들고 Electron으로 설치형 프로그램을 만든다.

개발 순서: M1 기본 프로그램 → M2 STEP 1·2 → M3 지형·도로 연결 → M4 연결 규칙 → M5 출력 → M6 모듈 건물 → M7 동기화. 완료 기준은 [05-MILESTONES.md](05-MILESTONES.md).

## 4. 좌표와 단위

- 내부 단위 m, 오른손 좌표계, Z-Up (X 동, Y 북, Z 위).
- 프로젝트 원점은 작업 영역 중심에 자동으로 정해지고 사용자가 바꿀 수 있다. 원점을 바꿔도 실제 배치는 그대로다.
- 프로젝트 원점, 건물 피벗, 부품 피벗은 서로 별개다.
- 입력(이미지 픽셀, 지도 경위도, 직접 입력 m)은 Reference 단계에서 프로젝트 좌표로 바꾸고, 엔진별 출력 단계에서 엔진 좌표로 바꾼다.
- GIS 좌표와 게임 월드 좌표는 분리하고 명시적으로 변환한다.

## 5. STEP 1 — Reference

**목표**: 어떤 레퍼런스든 축척과 좌표가 있는 공통 Reference 데이터로 만들어 STEP 2에 넘긴다.

**구성**: Image Workspace + Map Workspace → Reference Adapter → Reference 데이터. 두 Workspace는 같은 프로젝트와 좌표계를 쓴다.

### 기능
| 범위 | 기능 |
|---|---|
| 필수 | PNG/JPG/WebP 가져오기, 클립보드·드래그앤드롭, 이동·회전·크기, 레이어(생성·삭제·복제·순서·잠금·불투명도), 손그림(브러시·지우개·도형·선택) |
| 필수 | 축척 설정: 두 점 사이 실제 거리 입력. 원근 보정(네 점), 자르기 |
| 필수 | 지도 영역을 캡처해 Image Workspace로 가져와 편집. 이미지와 함께 범위·좌표계·m/px·회전을 저장하고 지도와 다시 겹쳐 볼 수 있다 |
| 필수 | 손그림·외부 캡처만으로 Image Workspace 단독 사용 |
| 필수 | 치수 보정: 0.5m 스냅(0.25/1/2m 선택) 보정값을 미리 보고 적용. 원본 치수 보존 |
| 후속 | PDF, OSM 데이터, PSD 레이어 유지, 고해상도 캡처, 메모 |
| 후속 | 이미지에서 도로·건물 후보 자동 추출 (아래 5.3) |

### 5.1 규칙
- 축척 모드: **실측 모드**(기준 거리·지도 좌표로 확정) / **자유 모드**(축척 없이 시작). 축척이 확정되지 않은 레퍼런스에 연결된 도형은 3D로 생성하지 않는다.
- 원본 이미지는 바꾸지 않는다. 자르기·원근 보정·편집 결과는 원본 ID·해시·변환 이력을 가진 별도 이미지다. 원근 보정 결과는 축척을 다시 확정한다.
- 축척을 다시 보정하면: 영향 계획을 먼저 보여주고 → 도형별로 선택하고 → 한 번에 적용(Undo 가능). 기본은 기존 좌표 유지. 높이·수치 속성·기존 3D 결과는 자동으로 바꾸지 않는다.
- AI가 추정한 치수와 사용자가 확정한 실측값은 구분해서 저장한다.
- 지도 이미지는 이용 조건을 지킨다. 현재 지도 소스는 OpenStreetMap 표준 화면이며 타일 대량 수집·오프라인 배포는 하지 않는다. 출처와 라이선스를 기록한다.

### 5.2 오픈소스 (전체 단계 정리는 [07-OPEN-SOURCE.md](07-OPEN-SOURCE.md))
| 이름 | 쓰는 이유 | 쓰는 방식 |
|---|---|---|
| MapLibre GL JS | 실제 지도 표시 | npm 라이브러리, Map Workspace |
| Terra Draw (+ MapLibre 어댑터) | 지도 위 선·폴리곤 그리기 | npm 라이브러리, STEP 2 그리기와 공유 |
| Turf.js | 길이·면적 계산 | npm 라이브러리 |
| OpenCV.js | 선·영역 후보 추출 | 외부 모듈, 별도 worker에서 실행 |
| PhotoCraft (Rust 이미지 편집기) | Image Workspace의 편집(브러시·레이어·선택), PSD 합성, 자르기·원근 보정 | 공식 CLI를 외부 프로세스로 실행. 소스를 Fork하지 않는다. 기능을 OpenCV와 중복 구현하지 않는다 |
| SAM 2 / SamGeo | 클릭 선택 분할, 위성·지도 의미 분할 | 후속 |
| BlenderGIS, OSM2World | GIS/DEM 처리 방식 | 알고리즘만 참고 (BlenderGIS는 GPL-3.0이므로 소스 사용 금지) |

### 5.3 이미지 → 2D 설계 데이터 변환
- 오픈소스로 **후보를 추출**하고, 사용자가 확인·수정·승인한 것만 설계 객체가 된다.
- 의미 변환(도로 중심선·폭, 건물 외곽선, 지형 구역, ID, 좌표)은 자체 개발 Adapter가 한다.
- 첫 단계는 수동 트레이싱 + OpenCV 후보. 범위의 나머지는 [06](06-OPEN-DECISIONS.md) 참고.

## 6. STEP 2 — 2D 설계

**목표**: 레퍼런스 위에 도로·건물·지형·수역·구역·프랍을 의미 있는 객체로 설계한다. 이 데이터가 레벨의 원본이다.

### 6.1 객체
| 객체 | 주요 속성 |
|---|---|
| Road | 중심선, 폭, 높이, 유형, 연결 노드, 지형 상호작용, 최대 경사 |
| Building | 외곽 폴리곤, 층수, 층고, 스타일, 블록아웃 수준(A/B/C) |
| Terrain | 경계 폴리곤, 높이 제어점, 등고선, 높이 브러시, 경계 방식, 재질 구역 |
| Water | 중심선 또는 영역, 폭, 깊이, 수위 |
| Zone | 영역, 용도, 밀도, 배치 제한 |
| Prop | 위치, 크기, 연결 에셋 |

- 도로는 그래프다. 도로 = Edge, 교차로 = Node. 첫 단계는 T자·십자 교차로만.
- 폴리곤·스플라인 편집, 정점 편집, 레이어·잠금·표시, 그룹.
- 선과 외곽선은 **직선과 곡선을 섞어** 그린다. 점마다 직선 꺾임 / 곡선(핸들로 휘는 정도 조절)을 고르고, 나중에 바꿀 수 있다.
- **모듈 규격 기반 설계**: 0.5m 설계 그리드와 모듈 호환 스냅으로 모듈로 나눌 수 없는 치수가 처음부터 생기지 않게 한다. 작업 모드는 모듈 설계(기본) / 실측 재현 / 자유 편집.

### 6.2 지형
- 경계 처리 3종을 모두 지원한다: **Cliff**(절벽), **Blend**(주변 지형과 자연 연결), **Platform**(플랫폼). 내부 높낮이와 경계 처리는 별개다.
- 높이 입력: 높이 브러시(올리기·내리기·평탄화), 높이 제어점, 등고선. 후속: Heightmap/DEM 가져오기, 노이즈.

### 6.3 지형 위 배치 — 객체마다 선택
| 방식 | 의미 | 예 |
|---|---|---|
| Follow | 지형을 따라감 | 일반 도로 |
| Conform | 지형을 평탄화·절토·성토 | 광장, 산악 도로, 일반 건물 바닥 |
| Foundation / Bridge | 기초·옹벽·교량·지지대로 보정 | 경사지 건물, 고가 도로 |

지원해야 할 레벨 유형: 자연 지형, 평탄화 구역, 절벽·고저차, 교량·입체 연결, 계단식 지형, 동굴·터널. **데이터 구조는 처음부터 이 모든 경우를 담을 수 있어야 한다.**

## 7. STEP 3 — 생성

**목표**: STEP 2 데이터를 규칙으로 3D 블록아웃으로 만든다.

### 7.1 생성기
| 종류 | 대상 |
|---|---|
| 영역 기반 | 건물 |
| 경로 기반 | 도로, 성벽, 수로 |
| 복합 | 성, 시장, 고가 구조물 (여러 생성기 조합) |
| 지형 | 높이 계산 → 메시 → Cliff/Blend/Platform 경계 |
| 기타 | 수면, 프랍 |

- 공통 모듈 라이브러리 위에 구조물별 생성기를 둔다. 지원 대상: 주택, 상점, 성, 성벽, 망루, 수로, 수문, 다리, 고가, 계단, 시장.
- 구조물 분류(Buildings / Fortifications / Waterworks / Infrastructure / Environment Structures / Compounds)와 건축 스타일은 서로 독립이다.

### 7.2 지형 계산
- 원본 지형은 보존하고, 변경은 **Terrain Modifier Stack**(평탄화·절토·성토·경사·침식·노이즈·마스크)으로 쌓는다. 건물을 지우면 그 건물이 만든 평탄화도 사라진다.
- 계산 순서(순환 금지): BaseTerrain → RoadProfile → BuildingPlacement → TerrainModifiers → ResolvedTerrain → Mesh.
- Heightmap으로 표현할 수 없는 동굴·터널·돌출 절벽은 별도 3D 메시로 만든다.

### 7.3 건물
- 생성 방식: **완성 건물 배치 + 모듈 자동 조립 + 스타일 변형**을 함께 쓴다.
- 조립 순서: 외곽선 분석 → 구조 분할 → 개구부 배치 → 지붕 생성 → 모듈 선택 → 검증.
- **블록아웃 수준**: A(기본 형태)부터 구현 → B(벽·층·지붕·문·창 분리, 피벗·이름 정리)가 기본 목표 → C(기둥·보·몰딩 등)는 건물별·부품별로 선택. 같은 건물 ID를 유지한 채 수준만 바꾼다.
- **남는 길이 처리 순서**: 모듈 조합 → 보조 모듈 → 길이 변형이 허용된 모듈만 조절 → 치수 변경 제안(승인 전 변경 없음) → 경고 후 수동 편집. 장식·문·창·코너는 늘리지 않는다.
- **복잡한 건물**: 직사각·L자·ㄷ자·단순 다각형은 자동 지원. 복잡한 지붕 교차부·비직각 코너·다층은 조건부. 특수 지붕·고딕 장식·비정형은 전용 모듈이나 Blender. 자동으로 못 만드는 구간은 실패시키지 않고 표시해서 사용자가 보완하고, 보완한 부분은 재생성 때 보호한다.
- **Recipe 구조**: Module Library → Building Recipe → Variant(예: Basic, Balcony, Chimney, Corner Shop) → Instance.
  - 부착 관계는 의미 단위로 저장한다(예: 2층·남쪽 벽·중앙).
  - 필수 구조 모듈은 삭제할 수 없다. 모듈 추가 시 연결 위치·치수·충돌·필수 부속을 검사한다.
  - Recipe를 고쳐도 기존 건물은 자동으로 바뀌지 않는다. 적용할 건물을 고른다.
- **모듈을 수정하면**: 기존 건물에 반영할지 선택한다. 외형만 바뀐 경우와 규격·연결점이 바뀐 경우를 구분하고, 변경 비교·영향 분석·미리보기·선택 적용·되돌리기를 제공한다.
- 모듈 메타데이터: 치수, 피벗, 정면 축, Socket(연결점), 분류, 반복·길이 변형 허용 여부, 머티리얼 슬롯, 스타일 태그(여러 개).
- 모듈 기본 규격(폭·층고·벽 두께)은 고정 표준이 아니라 **스타일별 프리셋**이다. 규격을 바꿔도 기존 건물은 유지되고, 선택한 건물에만 적용된다.

### 7.4 연결·충돌·재생성
- **연결 규칙** — 도면에서 구조물이 자동으로 생긴다.

| 조건 | 생기는 구조물 |
|---|---|
| 높이가 다른 지형이 만나는 경계 | 옹벽 |
| 도로가 높이 차가 있는 경계를 넘음 | 계단 또는 경사로 (선택) |
| 도로가 수로를 건넘 | 다리 |

  도면(도로 위치·폭, 구역 높이)을 바꾸면 관련 구조물만 다시 만든다. 개별 부품보다 **부품이 만나는 경계**(계단 맨 위와 땅 사이 틈, 높이 불일치)와 **사람이 지나갈 길**(경사·턱·끊김)을 따로 검사한다.
- **구조물 연결**: 연결 관계를 그래프로 자동 분석 → 폭·높이·방향·충돌 검사 → 변경 미리보기 → 승인 후 적용. 구성: Graph(관계) / Socket(위치·방향) / Dependency(영향) / Validator(틈·충돌) / Override.
  - 연결을 강제하지 않는다. 비율이 중요한 부품은 늘리지 않는다. 기준/종속 객체를 정해 순환을 막는다.
- **충돌**: 감지하면 해결 방법을 고르게 한다(위치·크기·기준점 조정, 지형 보정, 충돌 유지, 취소). 잠근 객체는 자동으로 옮기지 않는다. 경고 수준은 정보·경고·오류이며, 자기 교차 같은 오류는 생성을 멈춘다.
- **재생성**: 자동·수동 혼합. 바뀐 객체와 영향받는 객체만 다시 만든다.
  - 객체·속성 단위 잠금: Auto(자동 재계산) / Manual(변경 필요 표시 후 승인) / Locked(자동 변경 안 함) / Override(사용자 값 우선).
  - 잠근 객체도 충돌은 생길 수 있다. 이때 잠금을 무시하지 않고 경고와 해결 방법을 보여준다.
  - 큰 지형 변경, 교량 방식 변경, Blender 수정본 교체는 승인 후 적용한다.

### 7.5 오픈소스 (전체 단계 정리는 [07-OPEN-SOURCE.md](07-OPEN-SOURCE.md))
| 이름 | 쓰는 이유 | 쓰는 방식 |

| earcut | 폴리곤 삼각분할 | npm 라이브러리 |

## 8. STEP 4 — 3D 편집과 출력

### 8.1 편집 범위
- 이동·회전·크기, 벽·지붕·바닥 개별 선택
- 건물 외곽 **제어점** 이동(벽·지붕이 다시 계산됨), 제어점 추가·삭제, 지붕 능선·경사
- 문·창 위치·크기, 모듈 분할 간격
- 도로 폭·곡률·높이, 프랍 배치, 생성 모델을 기존 모델로 교체
- 파라미터 수정은 STEP 2 데이터를 바꾼 뒤 재생성한다. 직접 옮긴 것은 Override로 저장한다.
- 자유 메시 편집·UV·베이크는 Blender/Substance에서 한다.

### 8.2 검사
- 과경사, 충돌, 틈, 출입구 앞 공간 부족 경고
- 스타일별 모듈 규칙 확인 화면(Rule Inspector): 적용 스타일, 모듈 기준 폭, 남는 구간 처리 방식, 모듈 선택 이유, 자동/사용자 고정 여부. 3D 표시 토글(모듈 경계, Socket, 그리드, 보조 모듈, 규칙 경고)

### 8.3 Blender 출력
- 1 Blender Unit = 1m, Z-Up, 프로젝트 원점 = Blender 월드 원점
- 건물 피벗 = 바닥 기준점, 부품 피벗 = 모듈 규칙
- 건물별 Parent/Collection, ID가 들어간 규칙적 이름 (예: `BLD_001_House / _Wall_01 / _Roof_01 / _Floor_01 / _Door_01 / _Window_01`)
- 지형은 표면·절벽·측면·바닥을 분리하고 머티리얼 슬롯과 기본 UV를 보장한다
- 다시 가져올 때 ID로 원본 데이터와 연결한다. Blender에서 수정한 결과는 자동 생성이 덮어쓰지 않는다

### 8.4 엔진 출력 (Unreal 5.8, Unity 6)
- Unreal: Static Mesh, Actor, Material, Collision. Unity: Mesh, Prefab, Transform, Material, Collider. 엔진마다 Adapter를 둔다.
- 모델·텍스처 + Transform, Asset ID, 배치 데이터를 넘기고, 엔진 쪽에 최소한의 가져오기 스크립트(Unreal Editor / Unity Editor)를 둔다.
- 좌표 변환 프로필: Unreal `[100x, -100y, 100z]` cm, Unity `[-x, z, -y]` m (FBX 기준, 실측 검증됨).

## 9. 에셋 관리

### 9.1 라이브러리
- **공용 라이브러리**: 모델과 텍스처만 공유한다.
- **프로젝트**: 어떤 에셋의 어떤 파일 상태를 쓰는지 목록으로만 관리한다. 파일을 복제하지 않는다. 프로젝트 전용 에셋은 따로 둔다.
- 프로젝트 전용 에셋을 공용으로 등록해도 파일을 옮기지 않고, 원래 프로젝트의 참조는 그대로 둔다. Asset ID + 해시로 중복을 확인한다.
- 폴더는 정리용이다. 기능 구분은 태그·메타데이터로 한다(태그 여러 개 가능).
- 텍스처는 세 가지로 나누고 폴더도 분리한다.
  - **Trim Sheet / Tileable**: 등록, 중복 방지, 기본 머티리얼 자동 생성
  - **Special**(이끼·오염·마스크·데칼·노이즈): 이미지 파일만 등록. 처리는 엔진 프로젝트에서
- 스타일별 분류(예: 중세 목조, 고딕 석조, 일본 전통, 현대 건축)와 모듈 분류(Wall, Corner, Roof, Door, Window, Column, Floor 등).

### 9.2 버전 정책
- **에셋을 수정할 때마다 새 버전 에셋(v1, v2)을 만들지 않는다.** Asset ID는 그대로, 파일만 갱신한다. 과거 이력은 Git/LFS가 관리한다. 라이브러리에는 같은 에셋이 하나만 보인다.
- 프로젝트는 사용 중인 파일 해시(또는 commit)로 고정되고, 업데이트는 프로젝트별로 골라서 적용한다.
- 수정 유형별 처리:

| 변경 | 처리 |
|---|---|
| UV, 텍스처 | 갱신, 배치 유지 |
| 작은 형태 수정 | 갱신 + 영향 확인 |
| 구조·크기, Origin, 머티리얼 슬롯 | 영향 검사 후 적용 |
| 완전히 다른 모델 | 별도 에셋으로 등록 |

- 사용 중인 에셋은 삭제하지 않고 숨기거나 보관한다.

### 9.3 에셋 정보 화면 (Asset Inspector)
3D 미리보기(회전·확대), 텍스처 맵, 출처(Blender/Substance), 사용 중인 프로젝트, 파일 다운로드, 사용 위치 추적. 정점·삼각형·면·머티리얼·UV 채널·LOD·UV 겹침·텍셀 밀도·충돌 정보. 프로젝트별 검증 기준. 실제로 측정하지 않은 값은 표시하지 않는다.

### 9.4 Blender 연동
| 항목 | 내용 |
|---|---|
| 가져오기 | FBX/GLB 직접 가져오기를 먼저, Blender 애드온(등록·갱신·Studio에서 열기·검사)은 그다음 |
| 등록 단위 | 개별 모듈 / 그룹 / 완성형 중 선택. 오브젝트 1개 = 에셋 1개로 강제하지 않는다 |
| 데이터 소유 | 메시·UV = Blender. Socket·Recipe·배치·Override = Studio. 머티리얼 슬롯은 양쪽 확인. 마지막 공통 기준을 보관하고, 한쪽만 바뀌면 반영, 양쪽 다 바뀌면 충돌로 표시 후 선택 |
| 업데이트 | 개별 + 선택 일괄. 서로 의존하는 모듈은 묶어서 검증. 오류 모듈만 보류하고 나머지는 적용. Blender에서 지운 모듈은 Studio에서 자동 삭제하지 않는다 |
| 추적 | 이름이 아니라 고유 ID. 이름 변경은 자동 인식, 삭제·분리·병합·중복 ID는 사용자 확인. 애드온 없이 가져오면 후보만 제안하고 확실하지 않으면 자동 연결하지 않는다 |
| 원본 파일 | 에셋 하나에 .blend 여러 개 연결 가능. 업데이트할 원본을 고른다. 최신 수정 시각만으로 최종본을 정하지 않는다 |
| 다운로드 | FBX 기본, GLB 추가. 모델 단독 / 텍스처 ZIP / 전체 패키지 |
| 방향 | Blender → Studio 한 방향. 양방향 편집은 하지 않는다 |

### 9.5 머티리얼·텍스처
- 머티리얼과 파라미터는 **공유하지 않고 프로젝트마다** 만든다. 같은 프로젝트 안에서는 하나의 머티리얼을 여러 배치가 함께 쓴다.
- Studio는 FBX를 엔진에 넣을 때 **기본 PBR 머티리얼을 만들어 BaseColor·Normal·ORM을 연결**하고, **트림 같은 공용 텍스처가 엔진 프로젝트에 중복으로 들어가지 않게** 한다(Texture ID + 파일 해시).
- 연결은 Material Slot 단위다. FBX의 슬롯을 인식하고, Blender에서 이미 지정한 연결을 먼저 따르며 빠진 것만 채운다.
- 부위마다 다른 텍스처를 쓰는 경우와 같은 표면에 텍스처를 겹치는 경우를 모두 다룬다. 겹치는 텍스처(Special)는 추가 참조 정보로 넘기고, 특수 머티리얼은 사용자가 선택할 때만 만든다. 텍스처는 복제하지 않는다.
- 다시 가져올 때 기존 엔진 머티리얼을 덮어쓰지 않는다. 누락된 텍스처·슬롯은 경고만 하고, 사용자가 요청할 때만 고친다.
- 색공간: BaseColor sRGB, ORM·Roughness·Mask non-sRGB, Normal은 Normal 타입.
- **셰이더 생성·연결은 각 엔진 프로젝트(그 프로젝트를 작업하는 AI)가 맡는다.** Studio에 셰이더 매핑 기능은 넣지 않는다.

## 10. 저장·복구·동기화

- 프로그램은 PC마다 설치하고, 데이터는 Workspace 폴더로 분리한다.
- 로컬 저장이 먼저다. 저장은 원자적으로(임시 파일 → 교체) 하고, 실패하면 화면의 편집 내용을 유지한다.
- 프로그램이 업데이트돼도 이전 프로젝트를 열 수 있어야 한다. 마이그레이션: 버전 확인 → 백업 → 변환 → 미리보기 → 실패 시 원본 유지.
- 프로젝트마다 대상 엔진 버전을 저장하고, 엔진이 업데이트돼도 자동으로 바꾸지 않는다.
- **PC 간 자동 동기화는 필수다.** Git + Git LFS를 쓰고 Studio가 자동으로 처리한다. 사용자는 Git을 몰라도 된다.
  - 공용 라이브러리는 별도 저장소, 프로젝트는 프로젝트마다 저장소. Submodule은 쓰지 않는다.
  - 충돌이 나면 자동으로 덮어쓰지 않고 양쪽 작업을 보존한다.
  - 오프라인이면 로컬에 저장하고 나중에 동기화한다.
  - 흐름: 실행 시 확인 → Pull → 로컬 저장 → 검증 → 묶어서 Commit → Pull/병합 → Push.
  - 상태 표시: 동기화 완료 / 동기화 중 / 로컬 저장됨(미업로드) / 충돌 발생.
  - 일반 Git: JSON·Recipe·Manifest. LFS: FBX·GLB·PNG·TGA·EXR. 제외: 임시 파일·캐시·미리보기.
  - 원격 저장소는 **GitHub 비공개 저장소**를 쓴다. 연결은 선택이며, 연결 없이 로컬로 시작할 수 있다.

## 11. 화면 사용성

- 일상 작업(등록·갱신·배치·저장)은 한두 번 조작으로 끝난다.
- 에셋 갱신은 "파일 업데이트" 버튼 하나다. 자동으로 처리하는 것과 자동으로 적용하는 것을 구분한다.
- 화면은 3단계로 나눈다: 일반 작업 / 문제가 생겼을 때 확인 / 고급 관리(Git 설정, 이력 복원, Asset ID, 로그).
- 문제가 없으면 묻지 않고, 위험한 작업은 미리 알리고, 언제든 되돌릴 수 있다.
